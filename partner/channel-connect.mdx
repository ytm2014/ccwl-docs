---
title: "Channel Connect"
description: "Give a customer a link that connects their own WhatsApp number, with no dashboard login."
---

<Note>
Private beta, and switched on per partner. `GET /api/partner/channel-connect/settings`
tells you whether it is on for you.
</Note>

Your software gives one of your customers a link. They open it, connect their
own WhatsApp number on Meta's dialog, and the channel appears in their
workspace. Nobody logs into the dashboard, and no provider token ever reaches
your software or their browser.

All paths are relative to `/api/partner`, authenticated by your partner key as
`X-API-KEY`, from your backend only.

## What you can connect

| Platform | How |
| --- | --- |
| `whatsapp` | A hosted link, then Meta's own signup dialog. Add `"coexistence": true` to keep the number on the WhatsApp Business app. |
| Telegram | No link needed — post the BotFather token. |

<Warning>
`facebook`, `instagram`, `instagram_login` and `tiktok` are **not** supported
and are refused with a `422` on `platform`. On this platform those messaging
channels come from a connected publishing account, whose OAuth has to run in the
dashboard. Use the dashboard's client-invite link for them.

Channel Connect is about **messaging** channels. It does not connect publishing
accounts.
</Warning>

## 1. Register your return URLs

```bash
curl -X PUT https://app.example.com/api/partner/channel-connect/settings \
  -H "X-API-KEY: $PARTNER_KEY" -H "Content-Type: application/json" \
  -d '{"return_urls":["https://app.acmedealers.test/integrations/callback"]}'
```

Up to 20 HTTPS URLs, no credentials, query strings or fragments. **Matching is
exact**, including the path and any trailing slash. Removing a URL also stops
unfinished sessions from completing against it.

## 2. Create a connection

```bash
curl -X POST https://app.example.com/api/partner/workspaces/$WORKSPACE/channel-connections \
  -H "X-API-KEY: $PARTNER_KEY" -H "Content-Type: application/json" \
  -H "Idempotency-Key: dealer-4821-whatsapp-1" \
  -d '{
    "platform": "whatsapp",
    "return_url": "https://app.acmedealers.test/integrations/callback",
    "state": "dealer-4821"
  }'
```

```json Response
{
  "success": true,
  "data": {
    "id": "7f2c1a84-....",
    "workspace_id": "6b1f0e2c-....",
    "platform": "whatsapp",
    "coexistence": false,
    "status": "pending",
    "channel_id": null,
    "error_code": null,
    "state": "dealer-4821",
    "expires_at": "2026-10-20T09:42:00+00:00",
    "connect_url": "https://app.example.com/partner-connect/7f2c1a84-...?token=..."
  }
}
```

Open `connect_url` as a **top-level navigation** in your customer's browser —
not an iframe, not a fetch. Everything after they click Continue is bound to
that browser. The session lasts **30 minutes**.

`state` comes back to you on the return URL and in the completion event, so use
it to match the session to your own customer. Do not put secrets or personal
data in it; at most 500 characters.

`Idempotency-Key` (1–200 characters) is optional. The same key and the same
request returns the same connection with `200`; a different request on that key
is a `409`. Only a pending, unexpired session carries a `connect_url` — use a
new key to start over.

To **reconnect** an existing channel, pass its uuid as `channel_id`.

## 3. Read the result

Your customer comes back to your registered URL with `connection_id` and
`state`. That redirect is a hint, not the answer — read the authoritative
result:

```bash
curl https://app.example.com/api/partner/workspaces/$WORKSPACE/channel-connections/$CONNECTION \
  -H "X-API-KEY: $PARTNER_KEY"
```

| `status` | Meaning |
| --- | --- |
| `pending` | The link has not been used yet. |
| `authorizing` / `selecting` | In progress. |
| `connected` | Done. `channel_id` is the new channel. |
| `failed` | See `error_code`. |
| `cancelled` | The customer denied or closed the dialog, or you cancelled. |
| `expired` | The 30 minutes ran out. |

`connected` means the number was stored and subscribed. Whether messages
actually flow still depends on Meta account eligibility and messaging rules.

`POST …/channel-connections/{connection}/cancel` cancels an unfinished session.
Repeating it is safe, and it never disconnects a channel that already connected.

## Or subscribe

Rather than polling, subscribe the workspace's webhooks (with the `osk_` key you
issued for it) to `salesbot.channel.connection.completed`, `.failed`,
`.cancelled` and `.expired`. See [Events](/webhooks/events#channel-connect).

Delivery is at least once — **deduplicate on the envelope's `id`**.

## Telegram

```bash
curl -X POST https://app.example.com/api/partner/workspaces/$WORKSPACE/channels/telegram \
  -H "X-API-KEY: $PARTNER_KEY" -H "Content-Type: application/json" \
  -d '{"bot_token":"123456:ABC...","name":"Acme Motors"}'
```

`201` for a new channel, `200` for the same bot again (its channel is refreshed,
not duplicated).

A `422` on `bot_token` means the token was rejected, or the bot is the
platform's own bot, or it is already connected to another workspace, or the
plan's limit is reached.

A `422` on `takeover` means the bot's webhook points somewhere else. Connecting
it here stops that from receiving the bot's messages, so resend with
`"takeover": true` only if your customer confirms.

## Read channels

- `GET /api/partner/workspaces/{workspace}/channels` — `per_page` up to 100.
- `GET /api/partner/workspaces/{workspace}/channels/{channel}`

Both return the public channel fields only: never channel data or access tokens.

## Error codes

| Code | Meaning |
| --- | --- |
| `provider_not_supported` | That platform is not available here. |
| `provider_not_configured` | The platform is not set up on this instance for that channel. Contact the operator. |
| `provider_unavailable` | A transient failure starting the authorization. Retry with a new session. |
| `authorization_not_completed` | The dialog was closed or denied, or nothing could be stored — the number is already connected elsewhere, the plan's limits are full, or a permission was withheld. |
| `account_already_connected_elsewhere` | The number belongs to another workspace. |
| `channel_limit_reached` | The plan's connected-channel limit is full. |
| `reconnection_target_mismatch` | A reconnect came back with a different account than the channel it was meant to reconnect. The new one **is** connected. |
| `session_expired` | The 30 minutes ran out. |

Provider error bodies are deliberately not exposed. Fix the configuration, or
let your customer retry with a **new** session.

## Keep it safe

- The partner key stays on your server. It can act on every workspace you have
  provisioned.
- `connect_url` carries a one-session capability. Hand it straight to the
  customer's browser; do not log it, e-mail it or put it in an analytics event.
- A connection id is not a secret, but your `state` should be unguessable if you
  use it to resume anything on your side.
