The authoritative list for your workspace is [`GET /api/v1/workspace-webhooks/events`](/webhooks/manage#list-available-events). It includes each event's JSON schema and a sample. This page summarises it.

A field with no value is `null` or left out of `data`. IDs are always UUIDs.

## Publishing events

| Event | When |
| --- | --- |
| `publishing.account.added` | A social account is connected |
| `publishing.account.updated` | A social account changes |
| `publishing.account.disconnected` | A social account loses its connection, for example because the network refused its token. Sent once per lost connection; after a reconnect, the next loss sends it again. |
| `publishing.account.deleted` | A social account is removed |
| `publishing.post.scheduled` | A post is scheduled |
| `publishing.post.published` | A post is published on one of its accounts. Sent once for each account. |
| `publishing.post.published_all` | A post is published on every one of its accounts. Sent once per post. |
| `publishing.post.publishing_failed` | Publishing a post failed on one of its accounts. Sent once for each account. |
| `publishing.post.deleted` | Posts are deleted or moved to trash |

**Account events** carry the account's `id`, `name`, `provider` (for example `instagram`) and `status` (`connected` or `disconnected`). `account.deleted` carries `id` and `"deleted": true`.

**`post.scheduled` and `post.published_all`** carry the post's `id` and a numeric `status`. Fetch the full post with [Get a post](/publishing/posts/get-a-post).

**`post.deleted`** carries `ids` (a list of post IDs), `deleted` and `to_trash`.

```json
{ "event": "publishing.post.deleted", "data": { "ids": ["1e7d9b0a-..."], "deleted": false, "to_trash": true } }
```

## Messaging events

Messaging events are sent only while your plan includes the Messaging API. They can be limited to one channel per subscription: `whatsapp`, `facebook`, `instagram`, `sms` or `tiktok`, or `all`.

### Contacts

| Event | Data |
| --- | --- |
| `salesbot.contact.created` | `contact` |
| `salesbot.contact.updated` | `contact` |
| `salesbot.contact.tagged` | `contact`, `tag` |
| `salesbot.contact.untagged` | `contact`, `tag` |
| `salesbot.contact.stage_changed` | `contact`, `stage`, `previous_stage` |
| `salesbot.contact.date_reached` | `contact`, `event`, `date` (`field`, `value`) |

### Conversations and messages

| Event | Data |
| --- | --- |
| `salesbot.message.received` | `contact`, `conversation`, `message` |
| `salesbot.conversation.assigned` | `contact`, `conversation`, `assigned_to` (`name`) |
| `salesbot.conversation.closed` | `contact`, `conversation` (`id`, `status`) |
| `salesbot.message.sent` | `channel`, `provider`, `contact`, `conversation`, `message` |
| `salesbot.message.delivered` | same as `message.sent` |
| `salesbot.message.read_or_seen` | same as `message.sent` |
| `salesbot.message.failed` | same as `message.sent`, with `message.error_code` |

Not every channel reports every message status:

| Channel | Sent | Delivered | Read / seen | Failed |
| --- | --- | --- | --- | --- |
| WhatsApp | Yes | Yes | Limited | Yes |
| Facebook | Yes | Yes | Yes | Yes |
| Instagram | Yes | No | Yes | Yes |
| SMS | Yes | Limited | No | Yes |
| TikTok | No | No | No | No |

You can't subscribe a channel to a status it never reports.

### Automations and broadcasts

| Event | Data |
| --- | --- |
| `salesbot.automation.triggered` | `contact`, `automation` |
| `salesbot.automation.completed` | `contact`, `automation` |
| `salesbot.automation.failed` | `contact`, `automation` |
| `salesbot.broadcast.sent` | `broadcast` |
| `salesbot.broadcast.completed` | `broadcast` |
| `salesbot.broadcast.failed` | `broadcast` |

### Payments and bookings

| Event | Data |
| --- | --- |
| `salesbot.payment.succeeded` | `contact`, `payment` |
| `salesbot.payment.failed` | `contact`, `payment` |
| `salesbot.payment.refunded` | `contact`, `payment` |
| `salesbot.booking.created` | `contact`, `booking` |
| `salesbot.booking.rescheduled` | `contact`, `booking` |
| `salesbot.booking.cancelled` | `contact`, `booking` |

### Channel connections

Only on instances where partner-initiated onboarding is switched on, and
only for connections a partner started through the
[Client Connect API](/partner/client-connect) that have a messaging channel.
They report the outcome of the onboarding, not a later token expiry or
disconnection. The same connection also sends the
[Client Connect API](#client-connect-api) event.

| Event | Data |
| --- | --- |
| `salesbot.channel.connection.completed` | `channel`, `connection` |
| `salesbot.channel.connection.failed` | `channel`, `connection` |
| `salesbot.channel.connection.cancelled` | `channel`, `connection` |
| `salesbot.channel.connection.expired` | `channel`, `connection` |

`connection` carries `id` (the connection, not the channel), `platform`,
`status`, `channel_id` (only on `completed`), `error_code`, `state` and
`expires_at`.

```json
{
  "event": "salesbot.channel.connection.completed",
  "data": {
    "channel": "whatsapp",
    "connection": {
      "id": "7f2c1a84-...",
      "platform": "whatsapp",
      "status": "connected",
      "channel_id": "b4e9d201-...",
      "error_code": null,
      "state": "dealer-4821",
      "expires_at": "2026-10-20T09:42:00+00:00"
    }
  }
}
```

### Client Connect API

Only on instances where partner-initiated onboarding is switched on, and
only for connections a partner started. Every connection sends one, whatever the
provider, WhatsApp and Telegram included. They report the outcome of the connect
or reconnect link, not a later token expiry or disconnection (that is
`publishing.account.disconnected`). See [Client Connect API](/partner/client-connect).

| Event | Data |
| --- | --- |
| `publishing.account.connection.completed` | `connection` |
| `publishing.account.connection.failed` | `connection` |
| `publishing.account.connection.cancelled` | `connection` |
| `publishing.account.connection.expired` | `connection` |

`connection` carries `id` (the connection, not the account), `provider`,
`status`, `account_id` (the first account, only on `completed`), `account_ids`
(every account the link connected, only on `completed`), `channel_id` (only on
`completed`, and only when there is a messaging channel), `error_code`,
`state` and `expires_at`.

A connection with a messaging channel (WhatsApp, Telegram, Facebook Pages,
Instagram, TikTok, YouTube, LinkedIn pages, Google Business Profile, Threads,
Reddit, Mastodon and Bluesky) also sends the matching
`salesbot.channel.connection.*` event, in the
[Channel connections](#channel-connections) shape, with the same connection `id`.

```json
{
  "event": "publishing.account.connection.completed",
  "data": {
    "connection": {
      "id": "c6a1f0d2-...",
      "provider": "google_m_b",
      "status": "connected",
      "account_id": "9d3f6a10-...",
      "account_ids": ["9d3f6a10-..."],
      "channel_id": null,
      "error_code": null,
      "state": "dealer-4821",
      "expires_at": "2026-11-23T18:30:00+00:00"
    }
  }
}
```

### Store

All store events carry `event`, `contact` and `order`.

`salesbot.store.order_created`, `salesbot.store.order_paid`, `salesbot.store.payment_failed`, `salesbot.store.checkout_abandoned`, `salesbot.store.order_fulfilled`, `salesbot.store.order_cancelled`, `salesbot.store.order_refunded`, `salesbot.store.product_back_in_stock`, `salesbot.store.inventory_low`, `salesbot.store.customer_milestone`

## Data objects

| Object | Fields |
| --- | --- |
| `contact` | `id`, `name`, `email`, `phone`, `platform`, `stage`, `tags`, `created_at`, and `source` on `message.received` (see below) |
| `conversation` | `id`, `status` |
| `message` | `id`, `text`, `type`, `platform`, `direction`, `status`, `sent_at`, `status_at`, `error_code`, and `referral` on `message.received` (see below) |
| `automation` | `id`, `name`, `builder` |
| `broadcast` | `id`, `name`, `recipients`, `sent`, `failed` |
| `payment` | `id`, `provider`, `amount`, `currency`, `status`, `paid_at` |
| `booking` | `id`, `meeting_type`, `status`, `scheduled_at`, `ends_at` |
| `order` | `id`, `number`, `total`, `currency`, `status`, `provider` |

Text fields are capped at 1,000 characters (`message.text` at 10,000) and lists at 100 items. Contact and message events can include personal data such as names, emails, phone numbers and message text, so protect your receiver accordingly.

### Ad referrals on `message.received`

`salesbot.message.received` carries two extra fields that tell you which ad brought the person in. No other event changes.

- **`message.referral`**: the Click-to-WhatsApp, Click-to-Messenger or Click-to-Instagram ad, or `m.me` / `ig.me` ref link, this message came from. It's `null` on an ordinary message.
- **`contact.source`**: the contact's first touch, as text. For example `Messenger ad: 2021 Toyota Corolla LE`, `Instagram ad: Autumn sale`, `WhatsApp ad: ...` or `WhatsApp post: ...`. It's `null` when the contact didn't come from an ad.

`message.referral` is the same 12-key object the [Messaging API](/ad-referrals) returns:

| Key | Meaning |
| --- | --- |
| `source` | `ad`, `post` (a WhatsApp ad pointing at an organic post) or `link` (a ref link) |
| `ad_id`, `ad_title`, `body` | The ad's ID, headline and text |
| `photo_url`, `video_url`, `thumbnail_url` | The ad's image, video and video thumbnail |
| `source_url` | Link to the ad or post |
| `post_id` | The post the ad points at |
| `product_id` | For catalog ads, the catalog product the person tapped |
| `ref` | The `ref` parameter of the ad or link |
| `ctwa_clid` | Click ID (WhatsApp only) |

Every key is present, and `null` when Meta didn't send it. Links are only passed on when they are plain `http(s)` URLs with no username or password and at most 2,048 characters; any other link becomes `null`. Links are never shortened.

<Warning>
The media links are Meta CDN links and they expire. If you need the image or video later, copy it when the webhook arrives.
</Warning>

When someone taps an ad without writing anything, an inbound message reading `Opened the chat from an ad` is recorded with the referral, so you still get a `message.received` for the tap.

  "test": false,

## Link in Bio events

Link in Bio events have `"product": "biolinks"`. They are sent while your plan includes Link in Bio, and they always use `"channel": "all"`. Each change raises one event, whether it was made in the dashboard, through the [Link in Bio API](/biolinks/overview) or by an AI assistant. Content brought in by an import raises none.

| Event | When | Data |
| --- | --- | --- |
| `biolinks.lead.submitted` | Someone submits a form, email or phone block on a page | `submission`, `page`, `block`, `source` |
| `biolinks.submission.deleted` | A lead is deleted | `submission` (`id`) |
| `biolinks.page.created` | A page is created | `page`, `via` (`dashboard`, `api` or `template`) |
| `biolinks.page.published` | A page goes live | `page`, with `status` and `previous_status` |
| `biolinks.page.paused` | A page is paused | `page`, with `status` and `previous_status` |
| `biolinks.page.deleted` | A page is deleted | `page` (`id`, `slug`) |
| `biolinks.link.created` | A short link is created | `link` |
| `biolinks.link.status_changed` | A short link's status changes | `link`, with `previous_status` |
| `biolinks.link.deleted` | A short link is deleted | `link` (`id`) |
| `biolinks.link.click_milestone` | A page or short link reaches 100, 1,000, 10,000 or 100,000 clicks | `target` (`type` `page` or `link`, `id`, `url`), `milestone`, `total_clicks` |
| `biolinks.qr.created` | A QR code is created | `qr` (`id`, `target_type` `page`, `link` or `url`, `target_id`) |
| `biolinks.domain.verified` | A custom domain's DNS is verified | `domain`, `operation_id` |
| `biolinks.domain.ssl_active` | HTTPS is ready on a custom domain | `domain`, `operation_id` |
| `biolinks.domain.failed` | A domain operation started through the API fails | `domain`, `operation_id`, `reason_code` |

| Object | Fields |
| --- | --- |
| `page` | `id`, `slug`, `title`, `url`, `status` (`active` or `paused`). On `page.created` also `domain` (the custom domain's host, or `null`). |
| `link` | `id`, `title`, `short_url`, `destination_url`, `status` (`active` or `paused`) |
| `domain` | `id`, `host`, `status` (`verified` or `pending`), `ssl_status` (`active` or `pending`) |
| `submission` | `id`, `type` (`form`, `email` or `phone`), `fields` (`name`, `email`, `phone`, `message`), `created_at` |
| `block` | `id`, `type`, `title` of the block the lead came from |
| `source` | `referrer_host`, `utm_source`, `utm_medium`, `utm_campaign` of the page visit, when known. Never an IP address, user agent or cookie. |

### Lead contents

Lead form contents are personal data. An endpoint receives them only when a workspace admin set it up in the dashboard, or when it is managed by an API key that also has `biolinks:submissions:read`. Any other endpoint gets the lead's ID only:

```json
{ "event": "biolinks.lead.submitted", "data": { "submission": { "id": "6f1c2b9e-...", "fields": null } } }
```

Fetch the lead with the Link in Bio API if you need it. If a key loses `biolinks:submissions:read` or is revoked, deliveries of lead contents to the endpoints it manages are cancelled.

```json
{
  "event": "biolinks.lead.submitted",
  "product": "biolinks",
  "data": {
    "submission": {
      "id": "6f1c2b9e-...",
      "type": "form",
      "fields": { "name": "Ada Lovelace", "email": "ada@example.com", "phone": null, "message": "Do you cater?" },
      "created_at": "2026-11-07T12:00:00+00:00"
    },
    "page": { "id": "1e7d9b0a-...", "slug": "joes-pizza", "title": "Joe's Pizza", "url": "https://example.com/b/joes-pizza" },
    "block": { "id": "9c4d7e21-...", "type": "form", "title": "Contact us" },
    "source": { "referrer_host": "instagram.com", "utm_source": "instagram", "utm_medium": "social", "utm_campaign": "autumn" }
  }
}
```
