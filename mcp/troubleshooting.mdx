---
title: "Troubleshooting"
description: "Fix the common problems connecting an AI assistant."
---


| What you see | What to do |
| --- | --- |
| The app **couldn't connect** or **authentication failed** | Check the URL is exactly `https://app.example.com/mcp`, with `https://` and no trailing spaces, then try again. |
| "None of your workspaces can connect an AI assistant" | None of your workspaces has a plan that includes AI assistant (MCP) access. Ask the workspace owner, or change plan. |
| `401` / "Unauthenticated" with a token or key | The token or key is missing, mistyped, expired, revoked or deleted. Check the `Authorization: Bearer <token>` header (the MCP server does not read `x-api-key`), or create a new token under **Profile** > **API**. |
| "This token cannot be used with AI assistants…" or "This API key cannot be used with AI assistants…" | The token or key was created without the **AI assistants** permission. Create a new one with it. |
| "This API key is no longer authorized." | The person who created the workspace API key has left the workspace, so the key was revoked. A workspace admin can create a new one. |
| A tool is missing, or the assistant says the token or key does not include a permission | It was created without that permission. Create a new token or key that includes it. |
| "This connection is not linked to a workspace. Disconnect and reconnect it, and choose your workspaces when asked." | The sign-in connection has no workspaces. Remove the connector in your AI app, connect again and tick your workspaces. |
| "You no longer have access to any workspace this connection was set up for" | You left, or were removed from, every workspace you ticked. Connect again and tick the workspaces you can use now. |
| Sign-in errors on a connection that used to work | It went unused for 90 days, or was removed. Click **Connect** in your AI app and sign in again. |
| The assistant can't see a workspace | With a sign-in connection it only sees the workspaces you ticked: connect again and tick it too. With a personal access token, you are not a member of that workspace. A workspace API key only ever works in its own workspace. |
| "The MCP is not available on your current plan.", "The MCP is not available for this workspace." or "This workspace's plan does not include AI assistants." | That workspace's plan does not include AI assistant (MCP) access. Ask the workspace owner, or change plan. |
| "You do not have permission…" when creating or changing a post, or "Viewers can read through the MCP but cannot make changes." | The assistant acts as someone whose role in that workspace is **Viewer**: you, or for a workspace API key, the person who created it. Making changes needs **Member** or **Admin**. |
| Sales inbox tools are missing | The workspace's plan does not include the sales inbox, or your team role cannot open that area. |
| "The Salesbot API, webhooks and MCP tools are not included in your plan…" | The workspace's plan does not include the sales inbox tools for AI assistants. The publishing tools still work. An add-on or another plan adds them. |
| Bio Links tools are missing | Your platform does not offer the Link in Bio API, or, for the tools that create or change something, does not allow changes through it. A token or key also needs the matching Bio Links permissions. |
| "Bio Links tools come with every plan that includes Bio Links…" | The workspace's plan does not include Bio Links. |
| An account has no analytics, or its figures look incomplete | X accounts have no analytics. A newly connected account's first import takes a while; until it finishes, the answer's `initial_sync` says the figures are incomplete. |
| A post change or option was refused | Each refusal names the problem. Common ones: an option key the network does not accept (see `post_options` in `list-accounts`), an account's own version with more items than its network publishes, a `first_comment` when none of the post's accounts publishes one, or, on a scheduled post, a change that would leave an account unable to publish it. See [First comments, mentions and post options](/mcp/tools#first-comments-mentions-and-post-options). |
| A message or broadcast was refused | The assistant must pass `confirm: true` after checking with you, and the workspace may have reached its assistant sending cap (60 messages an hour, 200 people a day). The refusal says which. |
| "The workspace reached its active contacts limit, so messages can only go to contacts active in the last 30 days…" | The workspace is at its plan's active contacts limit. Contacts active in the last 30 days can still be messaged; for anyone else, add contacts to the plan with an add-on. Nothing was sent. |
| Nothing happens when you click **Connect** | Allow pop-ups and redirects for your AI app's site, or try another browser. |
| The app won't add an HTTP server | It only supports local (stdio) servers. Use the `mcp-remote` bridge shown in [Connect your app](/mcp/connect#use-a-personal-access-token). |
| The assistant can't see your posts or accounts | Make sure the connector is switched on for that chat, then ask it to "list my workspaces". |

Still stuck? Contact your platform's support with the name of your AI app and the exact error message.
