Your platform has a built-in **MCP (Model Context Protocol) server**. Connect an AI assistant to it and ask, in plain language, for the work you would otherwise do in the dashboard:

- "What's scheduled for next week?"
- "Draft a LinkedIn and X post announcing our webinar and schedule it for Tuesday at 10am."
- "Upload this image from a URL and add it to the queue for Instagram."
- "Find my failed posts and tell me what went wrong."
- "Which account grew most this month, and when should we post next?"
- "Which conversations in the inbox are still unread?"
- "Tag everyone who asked about pricing this week as `pricing-lead`."
- "Book Sam in for a demo on Thursday afternoon."

<Note>
AI assistant (MCP) access depends on your plan and on whether your platform has turned it on. If the server URL below returns `404`, it is not available to you yet.
</Note>

MCP is an open standard that Claude, ChatGPT, Cursor, VS Code, Claude Code and many other apps support. There is no integration code to write.

## The server URL

```
https://app.example.com/mcp
```

It uses streamable HTTP. It is the same address for every workspace: [connect your app](/mcp/connect) by signing in with your usual login (OAuth) and ticking the workspaces it may use, or by sending a personal access token or a workspace API key.

<Note>
The older address `https://app.example.com/os/mcp` still works, with sign-in as well as tokens and keys. Use `/mcp` for anything new: it is the address your dashboard gives.
</Note>

## Sign-in, token or API key

| | Sign in (OAuth) | Personal access token | Workspace API key |
| --- | --- | --- | --- |
| Set up | Paste the server URL, sign in, tick your workspaces | Create a token with the **AI assistants** permission, paste it into your app's config | A workspace admin creates a key with the **AI assistants** permission; paste it into your app's config |
| Workspaces | The workspaces you tick when you connect. Connect again to change them | Every workspace you belong to | The key's own workspace only |
| Acts as | You | You | The person who created the key, with the role they hold now |
| What it can do | Everything your role allows in those workspaces | What your role allows, narrowed to the token's permissions | What its creator's role allows, narrowed to the key's permissions |
| Best for | Claude, ChatGPT and other apps with connector screens | Claude Code, scripts, apps without OAuth | An assistant or tool that should only ever work in one workspace |
| Lasts | Refreshes itself. Unused for 90 days, sign in again | Until it expires (90 days unless you chose another date) or you revoke it | Until you revoke it, or the expiry date if you set one. It stops working if its creator leaves the workspace |

Whichever you use, the assistant can never do more than the role of the person it acts as allows in each workspace.

## How it works

Almost every tool works on one workspace. The assistant is told this when it connects, so you can just ask; behind the scenes it:

1. calls `list-workspaces` to get the workspace `uuid` (with a sign-in connection, only the workspaces you ticked; with a workspace API key, only the key's workspace),
2. passes that `uuid` as `workspace` to every other tool,
3. for posting, calls `list-accounts` for the account IDs, then `create-post`.

When the connection can only use one workspace (a workspace API key, or a sign-in connection with one workspace ticked), `workspace` is optional and the tools use that workspace.

## Roles and permissions

What the assistant may do follows your role in the workspace:

| Your role | Read | Create, edit, schedule, delete |
| --- | :---: | :---: |
| Viewer | ✅ | ❌ |
| Member | ✅ | ✅ |
| Admin | ✅ | ✅ |

Sales inbox tools also follow your team role: a tool for an area you cannot open in the dashboard is not offered at all. A viewer can read through the sales inbox tools but cannot change anything with them, whatever their team role. With a token or workspace API key created with permissions, the assistant also only gets the tools those permissions allow. If a workspace requires post approval, posts the assistant schedules or queues wait for approval like anyone else's.

A workspace you cannot access is reported as "not found", the same as one that does not exist.

## Safety rails

- **Sensitive changes need a yes.** Tools that message people, can start or change an automation, or cannot be undone refuse to run until the assistant passes `confirm: true`, which it should only do after checking with you: `send-message`, `send-template-message`, `submit-broadcast`, `close-conversation`, `create-contact`, `update-contact`, `book-appointment`, `reschedule-appointment`, `cancel-appointment`, `mark-appointment-outcome`, `create-automation`, `save-automation-flow` and `set-automation-state`.
- **Broadcasts are never sent by the assistant.** `submit-broadcast` creates the broadcast awaiting approval; a person approves it in the dashboard.
- **Automations are saved as drafts.** Nothing an assistant builds answers customers until someone presses Publish in the app.
- **A sending cap.** An assistant can send at most 60 messages an hour and reach 200 people a day per workspace. A send past the cap is refused with the reason.
- **Customer text is data.** Messages and notes written by your customers reach the assistant wrapped in `<untrusted_customer_content>` tags, with the instruction never to follow them.

## Timezones

Dates are stored in UTC. Most publishing tools take an optional `timezone` (an IANA name such as `Europe/London`) for reading your input and formatting the answer. Without one they use your account's timezone, then UTC, and every answer says which timezone it used. Analytics periods are UTC days; `get-best-posting-times` takes a `timezone` for its days, hours and next slots.
