The **REST API** card on the [Integrations](/guide/integrations/overview) page is where you give your own software, or a developer you work with, access to the workspace through the REST API. This page covers the dashboard side. For developers, [Quickstart](/quickstart) and [Authentication](/authentication) explain how to use a key.

You need the workspace **Admin** role. On some platforms the card first shows a short list of options (for example **Publishing** or **CRM & messaging**); pick the one you want to manage.

## Open the page

In the sidebar, open **Integrations**, then click the **REST API** card. The page lists **Workspace API keys**, your own personal tokens, and the **Base URLs** your developer needs.

## Workspace keys and personal tokens

| | Workspace key | Personal token |
| --- | --- | --- |
| Works in | This workspace only | Every workspace you belong to |
| Acts as | The Admin who created it | You, with your role in each workspace |
| Who sees it | Every Admin of this workspace | Only you, in **Profile** > **API** |
| Default expiry | No expiry | 90 days |

Use a workspace key for a system that belongs to the workspace (a CRM, a website form). Use a personal token for your own scripts or AI assistant across several workspaces.

## Create a key

<Steps>
  <Step title="Open the dialog">
    Click **Create API key**.
  </Step>
  <Step title="Choose where it works">
    Under **Where it works**, pick **This workspace only** for a workspace key, or **All my workspaces** for a personal token. If only one kind is available to you, the dialog skips this choice.
  </Step>
  <Step title="Name it and set an expiry">
    Enter a **Name** (for example "CRM integration") and pick an **Expiry**: 7, 30, 60 or 90 days, 1 year, **No expiry**, or **Choose a date**.
  </Step>
  <Step title="Pick permissions">
    Under **Permissions**, tick what the key may do. Permissions are grouped by product (Publishing, the sales inbox, Bio Links, Webhooks, AI assistants); use the select button above a group to tick all of it. Nothing is ticked by default, and permissions added to the product later are never granted to existing keys automatically.
  </Step>
  <Step title="Create and copy it">
    Click **Create key**. You may be asked to confirm your password. Click **Copy key**, store it safely, then click **Done**. The key is shown only once.
  </Step>
</Steps>

<Tip>
Connecting an AI assistant that can't sign in? Click **Key for an AI assistant** instead. It opens the same dialog with the AI assistant permissions already ticked. See [AI assistants (MCP)](/guide/integrations/ai-assistants).
</Tip>

## Read the list

Each workspace key shows:

| Column | What it shows |
| --- | --- |
| **Name** | The name, with a status: **Active**, **Expired** or **Revoked**. |
| **Key** | The first characters of the key, so you can recognise it. |
| **Permissions** | What the key may do; click to expand the full list. |
| **Last usage** | When it was last used; hover for the date per product. |
| **Created at** | When it was created and by whom. |
| **Expires at** | When it stops working, if ever. |

## Revoke or delete a key

- To stop a key working, click its revoke button and confirm with **Revoke key**. Every client using that key stops working at once; other keys are not affected.
- A revoked or expired key can then be removed from the list with its delete button. The activity log keeps its history.

To replace a key safely, create the new one, switch your integration to it and test it, then revoke the old one. A successful request only proves that one client works, so check every place the old key was used before you revoke it.

## Personal tokens and older keys

**Your personal tokens** lists the tokens you created with **All my workspaces**. You can revoke them here; to rename or rotate them, use **Manage in Profile > API**.

If the workspace still has keys from before workspace keys existed, they appear under **Older keys** and keep working. Use **Replace with a workspace key** to create a matching workspace key, update your integration, then revoke the older one.

## Keys created by other integrations

Connecting [Zapier](/guide/integrations/zapier) creates a workspace key for it. That key appears in the list too; revoking it here stops your Zaps, and disconnecting Zapier deletes it.

## Troubleshooting

- **"This workspace already has the most API keys it can hold."** A workspace can have up to 25 active workspace keys. Revoke one you no longer use, then try again.
- **A client suddenly gets "unauthenticated" errors.** Check the key's status in the list: it may have expired or been revoked. Create a new one.
- **There is no REST API card.** You need the **Admin** role, and your plan or platform must include API access.
